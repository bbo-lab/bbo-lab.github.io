Detailed Description

vidre/storage/raw.hh

The raw file format uses Type-Length-Value (TLV) encoding, inspired by the design principles of ASN.1, which is also used internally for packet transmissions.

The primary goals are:

  • Minimal computational overhead during recording
  • Self-describing structure (cf. BER encoding, X.690)
  • Storage size is intentionally traded off for speed

The raw file format is designed to be flexible and extensible, allowing for the inclusion of various types of data streams (e.g., video, audio, metadata) while maintaining a consistent structure. The use of TLV encoding facilitates the addition of new data types and structures without breaking compatibility.

Yet, the raw file format is not intended to be a general-purpose container format. It is specifically tailored for the needs of VidRe and may not be suitable for all use cases. For example, it may not be the best choice for long-term archival storage or for sharing data with external parties.

Therefore, VidRe also provides tools for converting raw files to more widely used formats (e.g., FFV1, MP4, AVI) for archival and sharing purposes. These tools are designed to preserve the integrity of the original data while providing compatibility with a broader range of software and platforms.

File layout

Each "raw" file consists of a preamble and a content header, followed by a sequence of data packets.

The preamble contains a magic number and version information, which are used to identify the file format and ensure compatibility:

<magic> // 8 bytes
<version> // 8 bytes (4 bytes major, 4 bytes minor)

Note that the magic number is designed to be read and written as a 64-bit integer, which also provides information about the endianness of the file.

The content header following the preamble contains metadata about the data streams recorded in the file, such as video frames, audio samples, and any associated metadata. Each stream has it's own definition of what is contained in the content header:

<isodate> // ISO 8601 date string (reference time and file creation time)
<timestamp> // Associated reference timestamp
<stream header>* // Definitions of the data streams (e.g., video, audio, metadata)
