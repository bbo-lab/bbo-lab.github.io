Detailed Description

Devices may be hard- or software devices. The latter applies, for example, to filters, and the like. Each device provides streams, ie. sinks and sources, as well as generic configuration options. Specific implementations will add more direct functionality.

Device configuration is stored internally as a JSON object, which is also returned by the info() method. This allows for a flexible and extensible way to store and retrieve device information, and also allows for user-defined configuration options. The general options are defined as follows:

  • device: A string that specifies the device class or type (e.g., "camera/uvc").
  • name: Human-readable name for the device, which should be unique. It can be used for display purposes and may be user-settable.
  • id: Unique identifier for the device, which can be used to reference it in settings and other contexts. If the device does not have a unique ID, it should return an empty string.
  • private: Map of device- or operating-system specific configuration options and information. The contents of this object are defined by the specific device implementation and may include details such as hardware parameters, stream configurations, and other relevant information.
  • preset: Presets. This should at least contain a "default" preset, which is used when the device is started without a specific preset (see setup() method).
  • setup: The actual device configuration (see setup() method).
  • config: List of configuration options for the device. This is used to generate user interfaces for configuring the device.

◆ setup()

virtual void vidre::device::base::setup ( const settings::json & = {})
pure virtual

Setup device.

This method is used to configure the device with specific settings. The exact configuration options depend on the device implementation.

There are three cases for how this method can be used:

  1. The device is not connected
  2. The device is connected but not running
  3. The device is running
Note
The setup() method should be called after connecting the device. It must be called at least once before starting the device. Depending on the device implementation, it may be possible to call setup() also in the running state with a subset of options.
See also
state::configured
